### Phase 1 对操作的含义

1. **上币/上线：** 生产关键路径仅为 **永续**（含 **XAUUSD**）。  
2. **准入：** 未打上 **经纪商 / 机构 / 做市商** 标签的 UID 不得交易。公众“注册”开着 = **L3**。  
3. **资金：** 进入永续账户的划转 **仅 USD/USDT**（来自 MT 账户或 X-fund）。其他资产不得上这条轨。  
4. **KRI/SOP：** 现货、杠杆、期权、理财条目仍文档化 — 视为**休眠**，除非有 Phase 2+ 豁免；日报优先永续、准入与资金轨道。  
5. **XAUUSD 永续：** 适用完整永续控制（标记/指数、资金费、杠杆档、保险/ADL），并关注贵金属时段/节假日流动性与间隙风险。

**用日常话说**

V-Exchange 是持牌店（ADGM / 毛里求斯）。**今天绿灯只亮永续合约**——跟踪某个价格、没有到期日的合同。黄金对美元（**XAUUSD**）是其中之一。零售客人**不能**从大街走进来，必须经**经纪商**（例如 Vantage 子品牌，或外部白标）。对冲基金和大客**线下开户、只走 API**。做市商走自己的接入。

钱不会直接掉进交易钱包。客户先**入金**到 **MT 账户** 或 **X-fund**，再把 **USD 或 USDT** **划入永续账户**。撮合、强平、清结算只看见这个账户。现货、USD 杠杆（逐仓和全仓）、跨币种保证金、组合保证金、期权、理财画在版图上是为了以后能开——开关现在是**关**的。

如果工单在说现货或杠杆，先当成**以后的作业**，不是今天的生产控制——除非风险已经签了 Phase 2+ 豁免。

## 零基础说明

不要求你以前做过交易。你需要知道的是：**出了事该叫谁、哪一颗按钮会伤人**。本节把行话翻成人话。

### 这家公司在干什么

这是 **Finprime V-Exchange**。获准进入的客户开立**永续账户**，把 **USD/USDT** 划进去，交易**永续合约**。看涨叫**做多**，看跌叫**做空**。因为可以用**杠杆**，价格小动就可能把抵押品亏光。这时系统会**强平**：强制平掉仓位，避免亏损传染给其他客户或公司。

一句话职责：**保住客户资产、让撮合诚实、别让错误价格或错误配置连环爆炸。**

### 每一页都会出现的词

| 你会看到的词 | 人话 | 为什么要管 |
|--------------|------|------------|
| **BU / PIC** | 业务单元 / 负责人 | 工单和后台权限都挂在这些名字上 |
| **SOP** | 标准作业程序，一份按编号执行的食谱 | 按顺序做；双人步骤不可因为“急”而跳过 |
| **KRI** | 关键风险指标，一只我们盯着的数字 | 绿=看着健康；黄 WARN=现在看；红 BREACH=现在动手 |
| **限额 Limit** | 系统或人必须遵守的上限 | 没有工单改限额，属于控制失效 |
| **Maker / Checker** | 两个人：一个提、一个批 | 重大变更禁止同一人兼任 |
| **RO / RO-OPS** | 风险官（定规则）/ 风险运维（7×24 值班） | 运维先确认告警；官做决定 |
| **ME** | 撮合引擎，配对买卖单的程序 | ME 错了，价格和强平都会错 |
| **RE** | 风控引擎，算保证金和强平的程序 | RE 错了，可能错杀健康用户或放过已破产仓 |
| **标记价 Mark** | 用于盈亏和“该不该强平”的公允价，不是最新成交 | 最新成交可能是薄单或操纵；标记更难被带偏 |
| **指数价 Index** | 多家外盘价格合成 | 指数陈旧或只剩一家坏源时，标记就不安全 |
| **资金费 Funding** | 多空之间定期付钱，让永续不要永远偏离真价 | 资金费极端时，行情看起来平静账户也会被压垮 |
| **保险基金** | 强平仍留下窟窿时用来填的钱池 | 不够时会走 **ADL**（从盈利对手仓上减仓） |
| **ADL** | 自动减仓 | 很罕见、很伤人。先确认保险真的不够 |
| **停牌 Halt** | 停止撮合新成交（永续还要决定强平是否继续） | 必须说清**范围**和**原因码** |
| **超护 Hypercare** | 变更后加盯（配置后常 24h，复牌后 4h，上线后 72h） | 没有超护责任人不要关单 |
| **Sev-1 / L4** | 最高事件 / 最高升级 | 客户资产或引擎完整性——开战时，不要一个人抠 |
| **SLA** | 必须在多少分钟内行动 | 确认超时会自动叫下一个人 |
| **RACI** | 执行 / 问责 / 咨询 / 知会 | **A** 能说“准”；**R** 负责去点 |

### 钱怎么走（简图）

1. **2C** 经**经纪商**进来（Vantage 子品牌或外部白标）。**2B** 对冲基金 / HNW **线下开户、只走 API**。**做市商**走流动性接入。  
2. **KYC / 合规** 然后 **开户**。  
3. **入金**到 **MT 账户** 或 **X-fund**，再把 **USD 或 USDT** **划入永续账户**。  
4. 下单；**撮合引擎**把两笔订单变成成交（开 / 持 / 平）。  
5. **风控引擎**不停问：“价格若反向跳，抵押还够不够？”  
6. 不够就开始**强平**。窟窿先由保险、再由 ADL 补。**清结算**记账。  
7. 从资金轨道**出金**。日终**对账**，核对账本、钱包、银行，避免把没有的钱打出去。

Phase 1 停在永续。生产上还没有“现货买完币再提出去”这条完整零售路径。

### 怎么读一份 SOP

每份 SOP 回答八个问题。哪一项是空的，**停下问风险运维**，不要自己编步骤。

1. **何时** — 什么事件启动（告警、时钟、有人申请）。  
2. **谁** — 谁输入、谁签字、必须告诉谁。  
3. **SLA** — 你有多少分钟。  
4. **前置** — 不满足就不要开做（应升级）。  
5. **如何做** — 编号步骤。双人步骤除书面“破窗”外，不得因紧急而省略。  
6. **系统** — 哪块屏幕或脚本。本手册里的 `/admin/...` 是**文档桩**（未来后台地图），不是正在跑的交易所。  
7. **完成** — 关单前要附什么证据。  
8. **升级** — 何时呼叫更高级别。

### 红黄绿灯习惯（RAG）

- **绿并不等于可以不理。** 先看**时间戳**。停更的绿灯是假绿（§9 情景族 **S9**）。  
- **黄 / WARN** = 有不对，你有的是分钟不是小时。先确认，再决定盯还是动。  
- **红 / BREACH** = 安全垫没了。先遏制，再写文章。  
- **Kill** = 停机。提现冻结、撮合总闸。永远两个人。

多灯变红时，**顺序很重要**。若**价格源先死**再爆强平，可能是按**错价**杀了人（族 **S2**）。若**外盘先崩**而我们的源仍健康，才是真下跌（族 **S1**）。§9 是侦探章。

### 入职第一周建议

1. 读本节、**Phase 1**、§2（角色）、§3.3（永续）、以及 §4 里你自己的 BU。  
2. 收藏告警台和值班表。  
3. 跟着 RO-OPS 把一笔告警从确认做到关闭。  
4. 练习一口气说停牌：**标的、原因、只停订单还是含强平、谁已经知道。**  
5. 在作为**旁观者**看过一次 G01 和一次 G04（双人）之前，不要自己改限额、切标记源或按 Kill。

### 例题 — 凌晨三点，一盏红灯（不需要交易背景）

你在 RO-OPS 值班。寻呼：**XAUUSD** 上 **PF-K01 红灯**。你从来没交易过黄金。

1. **5 分钟内确认**（G03）。这只表示“我看见了”，并不等于黄金修好了。
2. **看这只数字的时间戳**（PL-K06 / PF-K02）。时钟是旧的，可能是假红或假绿 — 走 ENG-03。不要拿陈旧时钟去强平或停牌。
3. **看交易所外面。** 黄金在其他场所是不是也在动？  
   - 外面平静、我们在尖叫 → 多半是 **S2**（公允价喂价错了）。暂停不安全的强平（RE-02），切源（RE-03）。  
   - 外面也在砸、我们的喂价健康 → 多半是 **S1**（真市场）。引擎还健康时优先 **只减仓**（PF-07），而不是一关了之。
4. 桥上一口气说：*“XAUUSD，PF-K01 红，我判 S2，强平已暂停，传播还没发。”*
5. **不要**为了让图好看去改标记公式。**不要**因为“又闪回绿了”就关告警。
6. 完整食谱：**PF-03**。侦探章：**§9**。

第一晚的全部工作就是：**看见、看时间戳、看外面、遏制、给情景族起名、写下来。**

**铁律**（为什么要有）

1. **禁止静默改限额** — 限额是安全帽（最高杠杆、最大仓、最大下单）。有人在后台改了却没有工单，事后无法还原是谁拆了栏杆。硬限额必须有工单、双人（A+ 级更多人）、审计记录。  
2. **职责分离** — 申请的人不能是批准的人。录入配置的人不能是唯一签字的人。这是为了防止疲惫或被盗的账号单独挪钱或加杠杆。  
3. **产品差异意识** — 现货、杠杆、永续是三台不同的机器。把现货价格带抄到永续、把永续强平抄到杠杆，会杀错人。工单必须标注 **SPOT / MARGIN / PERP**。  
4. **盘前 / 盘中 / 盘后** — 下单前（限额、KYC）、撮合中（价格带、STP、限频）、盘后（告警、对账、监察）。不能只靠一层。  
5. **客户资产优先** — 提现和托管的完整性，高于营收功能。  
6. **Phase 1 产品与准入门禁** — 生产交易 = **仅永续**（含 **XAUUSD**），在 **永续账户** 上用 **USD/USDT** 入金。准入 = **经纪商 / 机构 / 做市商**（2C 经经纪商）。现货、USD 杠杆、跨币种保证金、组合保证金、期权、理财、公众注册保持 **`[Phase 2+]`**。

## 2. 三道防线与角色映射

### 2.1 三道防线

银行和交易所共用一个简单想法：**开店的人不能既当裁判又给自己打分。**

| 防线 | 谁 | 人话 |
|------|-----|------|
| **第一道** | 产品 BU、交易运维、撮合、钱包、上币、做市 | 日常归你。你开控制、你盯、坏了你升级。不许说“风险会看见的”。 |
| **第二道** | 市场风险、信用/强平风险、模型风险、合规、法务 | 你写“能亏多少”、挑战第一道、跑独立监控。你不操作撮合引擎。 |

## 3. 产品入门（现货 / 杠杆 / 永续）

配置限额、写 SOP、选后台时用本节。只记一句：**Phase 1 生产是永续。现货和杠杆章节是预习，直到阶段门禁通过。**

### 3.1 现货 Spot `[Phase 2+]`

> **Phase 1 未启用。** 手册保留；不要打开产品。

**人话：** 现货就是“现金市场”。客户付全款拿到资产（或卖掉已有资产）。没有借款，也没有强平引擎。若 BTC/USDT 最新价 60,000，买 1 个 BTC 大约花 60,000 USDT 加手续费。就这笔交易本身，客户亏不完超过已付款（充提差错和欺诈另说）。

**风险仍要管：** 有人可以挂假盘、fat-finger 下巨单、上垃圾币、或从充提偷。

| 主题 | 风险含义 |
|------|----------|
| **是什么** | 标的/计价即时买卖；产品本身无杠杆 |
| **主要风险** | 操纵、fat-finger、上币质量、钱包结算、法币通道 |
| **关键控制** | 价格带（挡住离谱价）、最大下单、自成交防护（STP）、停牌、充提闸门 |
| **无强平引擎** | 客户亏损原则上以已付金额为限（充提差错除外） |
| **后台重点** | 交易对配置、费率档、STP、停复牌、行情元数据 |

### 3.2 杠杆 Margin（全仓与逐仓） `[Phase 2+]`

> **Phase 1 未启用。** 永续里说的“保证金”是另一回事（衍生品抵押）。工单里不要混用。

**人话：** 杠杆借贷是“我向平台借 USDT 去买更多资产，并付利息”。资产跌了，贷款可能超过抵押，于是**强制卖出**。**逐仓**只连坐那一个仓位；**全仓**会吃掉整个账户的抵押——亏损可能在同一账户里从一种币跳到另一种。

| 主题 | 风险含义 |
|------|----------|
| **是什么** | 借入资金放大现货敞口；借款计息 |
| **逐仓 Isolated** | 保证金与强平限于单一仓位/交易对 |
| **全仓 Cross** | 抵押品在账户内共享；账户内传染 |
| **主要风险** | 借款违约、强平缺口、利率配错、折扣不足 |
| **关键控制** | LTV/保证金率、分资产借款上限、利率曲线、强平瀑布、负余额自动还款 |
| **后台重点** | 抵押品档位、借款白名单、LTV 档、利率、强制平仓台 |

### 3.3 永续合约 Perps（U 本位 / 币本位） `[Phase 1]`

> **Phase 1 范围内：** 已批准永续，含 **XAUUSD 永续** 及其他永续；现货/杠杆关闭。

**人话：** 永续（perp）是跟踪标的价格（BTC、ETH、黄金兑美元……）且**永不到期**的合约。客户交抵押，可杠杆做多或做空。每隔若干小时，多空之间结算**资金费**，避免合约永远偏离真实世界价格。

**两种价格千万别混**

- **最新价** — 我们簿上刚撮合的那一笔。适合回答“刚才成交了什么”。单独拿来强平很危险：一笔薄单就能把它带走。  
- **标记价** — 用来算未实现盈亏和“你破产了没有”。通常来自**指数**（多家外盘）再加基差封顶。标记错了就会杀错人。这是情景族 **S2**。

**U 本位 vs 币本位：** 前者用稳定币（或类美元）结算；后者用标的币结算。Phase 1 值班也要知道本合同是哪一种，因为保险和盈亏单位不同。

**为什么 XAUUSD 要额外盯：** 金银/外汇会休息，加密指数可能 24×7。周末缺口和节假日流动性会让标记和最新价吵起来。关注开盘。

| 主题 | 风险含义 |
|------|----------|
| **是什么** | 无到期杠杆衍生品；资金费率在多空间交换 |
| **标记价 vs 最新价** | 标记价驱动未实现盈亏与强平；最新价用于撮合成交 |
| **主要风险** | 杠杆连环强平、保险基金耗尽、标记/指数操纵、极端资金费、ADL |
| **关键控制** | 分档杠杆、持仓名义上限、多交易所指数、资金费封顶、保险基金、ADL 队列 |
| **后台重点** | 杠杆档、风险限额、资金费公式、保险基金看板、ADL、熔断 |
| **Phase 1 示例** | **XAUUSD** 永续及其他已批准永续标的 |
| **Phase 1 额外关注** | 贵金属/外汇时段间隙、周末节假日流动性 vs 加密 24×7 指数交易时段 |

## 5. 跨 BU RACI 矩阵

### SOP-G01 — 限额变更（全产品）


**图 — SOP-G01 限额变更**

```mermaid
sequenceDiagram
  actor Req as "申请人"
  participant SYS as "系统 / RO-OPS"
  actor RO as "Maker RO"
  actor CHK as "Checker"
  participant RE as "风控引擎"
  Req->>SYS: 工单 旧到新 + 理由
  SYS->>RO: 影响包
  RO-->>Req: 驳回

  CHK->>RE: 四眼通过

  RE->>RE: 晋级配置 + 哈希
  RE->>SYS: 超护 24h
```

| 字段 | 明细 |
|------|------|
| **何时** | 软/硬限额、杠杆档、价格带、OI、LTV/折扣、借款上限、VIP 乘数等拟变更（定期校准或事中响应） |
| **谁** | **R** 申请人（PM/TO/RO/DA）· **A Maker** RO · **A+ Checker** RO2/CRO · **R 部署** RE · **C** ME、产品、零售影响时 CP · **I** RO-OPS；对客可见时传播 |
| **SLA** | 非紧急 ≤2 个工作日决策；紧急（进行中 BREACH）Maker ≤30 分、Checker ≤30 分；部署后超护 24h |
| **前置** | 标注 SPOT/MARGIN/PERP；旧→新数值；附压力影响（或 CRO 豁免）；同键无冲突在途 G01 |
| **系统** | 工单 · `/admin/risk/limits` · `waivers` · `/admin/risk-engine/configs` · `stress_testing.py` |

**这份 SOP 干什么：** 凡是会改“风险上限”的数字——最高杠杆、仓位、持仓上限、价格带、LTV、借款上限、VIP 乘数。“校准”是计划内微调；“临时”是风暴里改。

**如何做（不要跳；每步写了为什么）**
1. **申请人开工单。** 写产品标签（**PERP / SPOT / MARGIN**）、标的、字段名、**旧数字→新数字**、理由、关联哪条 KRI/事件、压力截图。若 CRO 豁免压力测试，用文字写明。*为什么：* 凌晨三点的下一个人不该靠猜。  
2. **系统 / RO-OPS 附影响包。** 现在离新上限有多近？30 天内有没有突破？会不会溅到别的产品？*为什么：* 批准一个已经快被吃完的更松上限，是连环爆的典型入口。  
3. **Maker（RO）决定：** 驳 / 批 / 附条件批（到期日、标的名单）。即使批准也要留评论。*为什么：* 沉默不是审计轨迹。  
4. **若是 A+ 级**（大名义、最高杠杆、保险相关或政策表），必须由**另一个人** Checker 再批。同一登录会被系统拒。*为什么：* 一个被盗或匆忙的账号不能单独拆栏杆。  
5. **RE 把配置从预发晋级到生产**，并把**配置版本哈希**贴回工单。*为什么：* 事后能证明引擎当时跑的是哪一版。  
6. **ME / 产品 ACK** 若变更对着交易（价格带、标的开关）。*为什么：* 风险不能给撮合惊喜。  
7. **RO-OPS 开 24h 超护**，把这条限额本该保护的 KRI 放进观察名单。*为什么：* 校准失败通常表现为 WARN 爆发，而不是一封礼貌邮件。  
8. **哈希 + ACK + 超护责任人都在工单上才能关。**

**完成：** 批准记录在案；生产哈希与工单一致；超护期内无归因于本次变更的异常突破。  
**升级：** 紧急缺 Checker→CRO 或指定代理人；部署失败→RE 回滚+L2；客诉飙升→传播+L3。  
**若跳过步骤：** 典型失败是“配置已上、工单是空的、没人盯”。按事件处理，不要当成缺纸。

**停牌如何做（桥上先说这些话）**
1. 值班 **TO** 建语音/聊天桥。前 30 秒说清：**范围**（单标的 / 板块 / 全局）、**原因码**、你猜的 **§9 情景族**（S1 真跌 vs S2 错标记…）。*为什么：* 别人若以为全站挂了，其实只是 XAUUSD，就帮不上忙。  
2. **RO** 批准（全局则 CRO）。批在工单上，不要只在聊天里。  
3. **ME** 按范围执行停/Kill，并*确认效果*：现货=不再成交；永续=不再接受增险订单（按设计）。贴截图或引擎标志。  
4. **RE（永续/杠杆）：** 决定**只停订单还是连强平一起停**。在腐烂的标记上继续强平等于抢用户的钱。按 RE-02。对传播说真话。  
5. **杠杆 TO：** 若涉及抵押，考虑 **MG-03** 冻借款。Phase 1 通常不适用。  
6. **钱包：** 默认**保持提现**。只有 CP/RO 下令才冻（客户资产或犯罪）。*为什么：* 行情恐慌时停提现会传成挤兑。  
7. **传播**发状态。永续文字**必须**写清资金费和强平是否还在跑。  
8. **记录员**在战时工单上记 UTC 时间线。不要明天靠回忆补。

**复牌如何做（不要“直接打开”）**
1. RO 确认根因已控。撮合健康为绿。永续须 **RE** 确认标记/指数新鲜（PL-K06 / PF-K02）。标记仍陈旧就还没完。  
2. 双 ACK：RO + ME（+ 产品）。三个名字，不是“会上大家都同意了”。  
3. 分阶段恢复：先看撤单风暴 → 打开价格带 → 正常。  
4. 超护**至少 4 小时**。

**升级：** 需要全局 Kill → L4 在 `/admin/engine/kill` 双控；停牌期间标记仍错 → 立刻 Sev-1。

| **SLA** | 确认：WARN≤15 分 · BREACH≤5 分 · Kill/客户资产≤2 分；分类说明确认后≤10 分；BREACH 遏制方案≤15 分 |

**这份 SOP 干什么：** 寻呼或风险门户亮了。确认的意思是“有人看见了”，不是“修好了”。没人确认，系统会自动叫下一个人。这是故意的。

**如何做**
1. **在 SLA 内在控制台确认**（WARN 15 分，BREACH 5 分，Kill/客户资产 2 分）。*为什么：* 确认能止住寻呼风暴，让其他人能干活。它不关闭事件。  
2. **看数字新不新。** 看管道时间戳（PL-K06 / PF-K02）。时钟是旧的，就给工单打“数据”标签，走 ENG-03。**禁止**在陈旧的红/绿上强平、停牌或改限额。  
3. **若数字是真的：** 写下主 KRI，列出 ±15 分钟内动过的其他 KRI，选 §9 情景族（S1–S12）。*为什么：* 避免把错标记当成真崩盘。  
4. **按该族手册遏制。** 核对应自动动作有没有打出；该打没打，是第二起事件。  
5. **定 L1–L4**，按 §8.2 呼叫。说清下一步谁负责。  
6. **Sev-1/2：** 开战时；5 个工作日内排复盘，趁还记得。

**升级：** 确认超时自动呼 RO；两次 BREACH 仍无遏制 → L3。

### SOP-G04 — Maker–Checker 与职责分离

| 字段 | 明细 |
|------|------|
| **何时** | A+ 限额、Kill、密钥仪式、制裁覆盖、保险注资、解冻、A+ 杠杆权限等 |
| **谁** | Maker ≠ Checker ≠ 受益交易员；**SYS** 强制；政策 **A** CRO/CISO |
| **SLA** | 无 Checker 不得变更生产；破窗 ≤15 分且自动工单+呼叫 |

**这份 SOP 干什么：** 防止一个人（或一台被偷的电脑）单独拆安全栏杆。“四眼”= 两双人眼、两个登录。

**规则**
1. 交易员**不能**批准自己的杠杆或权限。工作流必须拒绝同一 UID。  
2. 部署 A 级配置的 RE 工程师**不能**当唯一审批人。  
3. 钱包密钥仪式：至少两人（宜三人），并写下仪式 ID。旧材料销毁或登记作废。  
4. **解除**合规冻结需要第二名合规或 RO。加上冻结可以快；拿掉才是危险方向。  
5. **破窗**（紧急权限）：限时账号、自动工单（PL-K07）、当天复核。用了破窗，没有复核就不算做完。

**升级：** 哪怕只是*尝试*同一人自批 → 当安全事件 ENG-04 / L3，不要当成界面故障。

### SOP-G05 — 日终对账与结算

| 字段 | 明细 |
|------|------|
| **何时** | 每日 UTC 日切（重大交易事件后可加做） |
| **谁** | **R 匹配** ENG/SYS · **R 例外** 清算/TO · **Checker** 重大时 CO2/RO · **A 结算** TS |
| **SLA** | 日切后 ≤60 分出匹配；重大例外 ≤4h 老化；仅 `SettlementReady` 后打款 |

**这份 SOP 干什么：** 在资金打款前，证明我们的账和真实世界一致。EOD 是某个 UTC 日切。错了可能给客户打两遍钱，或看不见保险基金的窟窿。

**如何做**
1. 系统跑匹配：内部成交/余额 vs 账本、经纪商、链、银行 → `ReconLine` 列表（已配 / 未配 / 差异）。  
2. 清算/TO **认领每一笔差异**：重拉数据、带工单调整、或追外部场所。不许把差异留在“其他”。  
3. 金额超过公布的重要性：批准前必须 **maker–checker**。  
4. 文件干净（或 RO 豁免）后系统才发 **`SettlementReady`**。这是绿灯，不是 Slack 一个赞。  
5. **TS** 打款或上链，并把银行回单/txid 存进证据包。  
6. 按合规政策留存。

**升级：** 缺账无法解释 → L2/L3，并评估是否该暂停交易。

#### RM 风险运维

##### RM-01 每日风险包

**这份 SOP 干什么：** 每天印一张“我们安全吗”的报纸，让下一班和 CRO 不要从白纸开始。这不是交易。

| 字段 | 明细 |
|------|------|
| **何时** | 每个 UTC 日切（默认 22:00）；L3 当天再加做 |
| **谁** | **R** 系统拼装 · **A** RO 阅读并写评语 · **C** 例外时 PM/TO · **I** CRO（摘要） |
| **SLA** | 日切后 ≤90 分发出 |
| **系统** | `/admin/risk/reports` · `risk_reporting.py` |

**如何做（不要跳）**
1. 确认日切真的完成了（撮合、风控引擎、钱包喂价的时间戳 ≥ 日切）。*为什么：* 卡死的喂价拼出来的包会是假绿（情景族 S9）。
2. 跑 `risk_reporting.py`（或门户任务），拉：各台/公司快照、未关闭 WARN/BREACH、压力测试要点、7 天内到期的豁免。
3. 按 §8 给各家族涂红黄绿，**颜色旁边写喂价时间戳**。
4. 发给邮件组。RO 对每一盏黄/红写一句评语——沉默不算审阅。
5. 在门户确认。包晚了超过 2 小时，按 **ENG-03**（管道）处理，不是“我们忙”。

**完成：** 邮件/门户已发且 RO 点过确认。**升级：** 晚 >2h → ENG-03；数字和实时告警台打架 → 当数据事件，不要“先改 PDF”。

##### RM-02 WARN（黄灯）响应

**这份 SOP 干什么：** 黄灯。有不对。你有的是分钟不是小时。黄灯**不是**“等到红再管”的许可证。

| 字段 | 明细 |
|------|------|
| **何时** | §8 任一黄灯 |
| **谁** | **R** RO-OPS · **C** 对应产品 BU PIC · **A** 超时未处理则 RO |
| **SLA** | 15 分确认；30–60 分有书面方案 |

**如何做**
1. 在控制台确认（SOP-G03）。*为什么：* 确认能止住寻呼风暴，让你有空思考。
2. 看时间戳（PL-K06 / PF-K02）。陈旧的黄 → ENG-03，不要改限额。
3. 写一句：“这像 S?，因为……”。列出 ±15 分钟内动过的其他 KRI。
4. 决定 **盯**（留下一个复查时刻）还是 **动**（现在就开 G01/G02/PF-* 草稿）。数字在往红走，就在还黄的时候把下一步 SOP 预开好。*为什么：* 红灯再找 Checker 来不及。
5. 颜色变绿或已经升级之前，黄灯工单不要关。

**完成：** 黄灯消除或已升级并有工单。**升级：** 同一家族两盏黄灯还没方案 → 当 L2。

##### RM-03 BREACH（红灯）响应

**这份 SOP 干什么：** 红灯。安全垫没了。先遏制，再写文章。

| 字段 | 明细 |
|------|------|
| **何时** | 红灯或接近 Kill |
| **谁** | **R** RO-OPS + 产品 BU PIC · **A** RO · L3+ 呼叫 CRO |
| **SLA** | 5 分确认；15 分遏制 |

**如何做**
1. 确认（G03）。桥上说清：范围、KRI 编号、你猜的 §9 情景族。
2. **立刻按产品遏制：** 永续优先只减仓（PF-07）；杠杆 `[Phase 2+]` 考虑冻借款（MG-03）；现货 `[Phase 2+]` 考虑停牌（G02）。*为什么：* 没人改模式，引擎会继续撮合。
3. 核对应自动动作打没打出。该打没打，是**第二起**事件（引擎），不是脚注。
4. 按 §8.2 定 L1–L4。Sev-1/2 → 战时（§10）。客户资产不要一个人抠。
5. 遏制有了永久修复负责人之前，不要点“关闭告警”。关告警 ≠ 遏制。

**完成：** 已遏制 + 永久修复有名字。**升级：** 15 分仍无遏制 → 自动 L3。

##### RM-04 杠杆 / 权限上调

**这份 SOP 干什么：** 交易员或 VIP 想借更多风险（更高杠杆、更大仓位上限）。这不是客服人情，是一笔信用决定。

| 字段 | 明细 |
|------|------|
| **何时** | TR/VIP 提交购买力或杠杆申请 |
| **谁** | **R 提交** 交易员 · **R 资格包** 系统 · **A Maker** RO · **Checker** A+ 时 RO2/PM · **R 推送** ENG/RE |
| **SLA** | 资格包自动 <5 分 · Maker ≤1 个工作日（紧急 1h） |

**如何做**
1. 在 `trader_rights_workflow` 提交（私聊不能当唯一记录）。
2. 系统出资格包：近期盈亏/回撤、合规冻结、当前占用、未结坏账。*为什么：* 这个月赚了钱，也不能无视合规冻结。

**完成：** 状态 APPROVED 且线上限额与工单一致。**升级：** 有人试图批自己的 UID → 安全事件，不是界面故障。

#### SP 现货 `[Phase 2+]`

> Phase 1：这些是**预习材料**。不要打开现货交易对。

##### SP-01 现货上线

**这份 SOP 干什么：** 把一个已尽调的币变成大家能买卖的订单簿。上币意见（LD-01）不等于“按钮已经是绿的”。

| 字段 | 明细 |
|------|------|
| **何时** | LD-01 / G06 后门禁到齐 |
| **谁** | **R** 现货 PM + TO · **A** 风险+合规已放行 · **C** 钱包、做市、撮合 |
| **SLA** | 对外宣布的上线窗口当天清单勾完 |

**如何做**
1. 确认**正确链**的充提（错链 = 客户钱掉进洞）。
2. 配最小变动价、手数、价格带、STP、费率。*为什么：* 6 万美金的币若 tick 是 0.00000001，有人会拿来刷簿。
3. 做市 SLA **或**公开“薄盘”披露。沉默不是披露。
4. 预发测停牌。停不了就不要上。
5. 接通 SP-K01/02/03/05。点名 72h 超护。
6. 开关真的亮了再宣布。

**完成：** §11.5 勾完；超护有名字。

##### SP-02 现货停牌

停止该交易对的买卖撮合。默认**保持提现**，免得看起来像挤兑。跟 **G02** 现货列：TO 提议、RO 批、ME ≤2 分执行、传播发状态。原因码写进工单。

**完成：** `/admin/spot/halt` 状态与意图一致。

##### SP-03 现货复牌

不要对着空簿打印假价格。RO+ME 确认根因已消失（不是“看起来安静了”）→ 验簿、做市确实在报价 → 分阶段打开（先窄带）→ 超护 4 小时。

##### SP-04 价格带 / 名义上限

价格带是篱笆：离参考价太远的订单会被拒。改它走 **G01**（A+ 要两个人），然后 `/admin/spot/bands`，再盯 SP-K03。

##### SP-05 对倒 / 自成交移交

**这份 SOP 干什么：** 同一经济主体左右手成交刷量。你不是侦探——合规才是。你的工作是**尽快交证据**，并且不要偷偷把 STP（自成交防护）调松。

**如何做：** 保全订单/成交 ID → ≤30 分开合规案 → 可考虑 CP-02 冻结 → **禁止**“把 STP 调弱好让客户成交”。

#### MG 杠杆 `[Phase 2+]`

> Phase 1：没有借贷簿。不要把这里的“保证金”和永续里的抵押搞混——永续走 PF / RE。

**人话：** 客户抵押币，**借入**（多为稳定币），买更多币，付利息。币跌了就**强制卖掉**。**逐仓**只连坐那一个仓；**全仓**会吃掉整个账户的抵押。

##### MG-01 新增抵押品

**如何做**
1. LD-03 之后，量化压测**折扣**（一张爱跳的币面值 100，我们可能只当 70）。*为什么：* 还没卖掉它可能先跌。
2. 设 LTV 档、借款上限、利率曲线。
3. 逐仓和全仓的强平路径都演练过，才启用。

##### MG-02 折扣 / LTV 变更

走 G01。脱锚紧急：≤30 分双批。对客不利（可能因参数变化被强平）必须告知。盯 MG-K02/03。

##### MG-03 冻借款

**这份 SOP 干什么：** 停止某资产的**新借**（例如 USDT），避免轧空或脱锚抽干库存。已经借出去的还在。

**如何做：** `/admin/margin/borrow` 冻结 → 可选拉满利率 → 对客可见则公告 → **把解冻标准写进工单**（否则冻结会永远挂着）。

##### MG-04 强制平仓手册

**如何做**
1. 先确认标记新鲜。标记烂了 → **RE-02 暂停**。按错价强平等于抢用户的钱。
2. 标记好：保队列在排、限增险、永远不要删强平历史。
3. 延迟 >30 秒 → L3（引擎已经落后于市场）。

##### MG-05 坏账核销 / 追偿

缺口出现后：定量 → 自动还款 → 追用户 → 残余核销必须两个人 → 教训回流到折扣/缓冲。资金入账；这不是聊天里的“四舍五入”。

##### MG-06 利率曲线更新

MG-K07（计提例外）还红时不要推新曲线——会把错误利滚利。重大变更走 G01。

#### PF 永续 `[Phase 1]`

**这是今天真正在跑的路径。请读完每一张。** 永续（perp）跟踪某个价格（比特币、黄金兑美元……）且**永不到期**。客户交抵押，杠杆做多或做空。盈亏和强平看的是**标记价**（多家外盘合成的公允价），**不是**我们簿上最新一笔成交。

##### PF-01 新合约上线

**这份 SOP 干什么：** 把一份新合约（例如另一个金属对，或新的 BTC 永续）放到经纪商 / 机构 / 做市客户面前。漏勾一项，就是没保险或只有一家指数源就上线。

| 字段 | 明细 |
|------|------|
| **何时** | LD-04 + G06 完成 |
| **谁** | **R** 合约 PM · **A** RO · **C** RE / ME / DA / TS |
| **如何做** | 两个人对着 §11.3 **读出声来**：规格签字；指数成分够数且 PF-K01/K02 告警开；杠杆档双批；保险种子到位；资金费封顶测过；强平+ADL 演练签字；撮合标的与限频；客服话术写清资金费/强平；72h 超护点名；RO-OPS 能讲清**这一标的**如何区分 S2（错标记）和 S1（真下跌）。 |
| **完成** | 已上线，且 PF-K01/02/06/07 看板为绿**并带新鲜时间戳**。缺一项就不上。 |

##### PF-02 改杠杆档

**这份 SOP 干什么：** “这个合约 / 这一档名义最高能加几倍杠杆”。往上调，等于让用户更快亏光抵押。这是 G01，不是产品实验。

**如何做**
1. 数一数有多少用户贴着上限、持仓量会跳多少。
2. G01 双控 → `/admin/futures/leverage` → 24h 超护**盯强平量**（PF-K06）。*为什么：* “只是小小改一档”是常见的 Sev 级失误。

##### PF-03 标记–指数偏离响应

**这份 SOP 干什么：** 永续最重要的闹钟。**标记**应贴近**指数**（其他交易所均价）。两者裂开，要么世界真动了（基差），要么**我们的数字错了**（可能错杀健康用户）。

| 字段 | 明细 |
|------|------|
| **何时** | PF-K01 黄/红 |
| **谁** | **R** RO-OPS + RE + 量化 · **A** RO · **C** TO-FUT |
| **SLA** | 红灯分流 ≤5 分 |

**如何做（桥上先说这些）**
1. **时钟：** PF-K01 何时动的？**PL-K06**（管道延迟）或 **PF-K02**（指数某所陈旧）是不是*先*动？*为什么：* 谁先动，用来区分 S2（数据）和 S1（真市场）。
2. 看**外盘**（真实黄金/BTC 市场）。外面平静我们在尖叫，就信 S2。
3. **若是数据（S2）：** 切源（RE-03）。标记不安全则**暂停强平**（RE-02），考虑只减仓（PF-07）。对传播说：“公允价喂价不健康，强平已暂停”，不要说“市场关闭了”。
4. **若是真基差：** 指数诚实，只是我们的簿离得远。可只减仓。**禁止**为了让图好看去改标记公式。
5. 任何公式变更必须 **RO+量化双控**。没有“先改再补单”。

**完成：** 偏离有解释，且喂价已健康或交易已遏制。**升级：** 疑似错标记上已经跑过强平 → Sev-1。

##### PF-04 资金费极端 / 暂停

**这份 SOP 干什么：** 每隔 1 或 8 小时（按设计），多头付给空头或反过来，免得永续永远漂离真价。**封顶（钳制）**不让费率变成无穷大。客户抱怨“费率贵”**不是**关掉它的理由。

**如何做**
1. 确认封顶真的生效了（PF-K03）。生效了说明系统在干活。
2. 只有结算完整性坏了（公式错、付了两遍）才允许暂停结算。RO+产品双人，传播必须写明资金费已暂停。
3. 恢复须 RO 确认。

##### PF-05 保险赔付复核

当天快报：破产价、强平及不及时、做市在不在。数字对不上账就升级。然后 RM-06 / 可能 TS-04 注资。

##### PF-06 ADL 启动复核

**这份 SOP 干什么：** 自动减仓。保险填不起窟窿时，从**盈利的对手仓**上减。赢家会觉得不公平。这是最后一道阀门。

**如何做**
1. 先证明保险**真的不够**（PF-K07 应在 PF-K08 **之前**变黄/红）。若 ADL 先响，触发配错 → **立刻停 ADL + Sev-1**。
2. 核对减仓排名是否为已公布规则（常见是高杠杆/高盈利优先——以现行政策为准）。
3. 对客通知发出。模式古怪则合规查滥用。

##### PF-07 停牌 / 只减仓

**只减仓** = 可以平仓或把仓变小，**不能**变大。引擎还健康时，优先只减仓而不是一关了之。全停走 G02。传播**必须**说明资金费和强平还在不在跑。

##### PF-08 指数成分故障

指数是多家外盘的平均。一家死了或乱报价，按政策**踢掉**。剩下的少于最少家数 → **保护标记**并只减仓/暂停强平。临时改权重要 RO 签字。没有签字就“只用某一家”等于把操纵入口开成单点。

#### ME 撮合

**人话：** 撮合引擎是把一笔买单和一笔卖单变成成交的程序。它错了，所有用那个价格算的盈亏和强平都会错。把它当成控制室：开关很小，必须双人。

##### ME-01 发布 / 回滚

**如何做**
1. 变更工单写清会不一样的地方、以及怎么回滚（演练过的，不是“我们记得”）。
2. 先金丝雀（很小一部分流量）。盯时延 SP-K09 和撤单比 SP-K04。
3. Sev-1 时延或完整性：≤15 分决定回滚。红簿上逞英雄打热修复，是第二起事件的温床。

##### ME-02 撮合停机

业务停牌（G02）要 RO 批。**全局 Kill**（整站）是 `/admin/engine/kill` 上两个人。确认效果（不再成交）并通知 RE，避免冻结的簿上强平还在跑。不要让一个分片在交易、另一个已停，却不说出来。

##### ME-03 双活切换

宣告事件 → `/admin/engine/failover` 引流/切换 → **ME-05** 证明订单簿还是同一本 → 若已停牌则按 G02 复牌。没有校验和的切换只是传闻。

##### ME-04 撤单风暴抑制

撤单太多会饿死真成交。小心加限频或降载；若是单一 UID 在刷，交合规（滥用）。保护时延 SLO；不要“为了 VIP 高兴把水管开到最大”。

##### ME-05 故障后验簿

对比订单簿校验和与成交连续性。**完全复牌前把对比结果签在工单上。** *为什么：* 对着重建出来的垃圾簿复牌，会打印假价格和假强平。

#### RE 风控引擎

**人话：** 这个程序不停问“价格若跳，这个用户抵押还够不够？”它算**保证金率**、**破产价**，并**启动强平**。这里配错比博客写错危险——它在动真金。

##### RE-01 配置晋级

**如何做**
1. 必须带着 **G01 工单号** 和一份能读懂的 diff。
2. 先预发再生产。**配置哈希**贴回工单。
3. 呼叫 RO-OPS 开 24h 超护。
4. 没有工单就晋级 → **回滚 + 审计**。没有“紧急直接贴进生产”。

##### RE-02 强平引擎暂停 / 恢复

**这份 SOP 干什么：** 停掉强制平仓的机器人。做这件事是因为**它用的价格不安全**，不是因为用户抱怨“被公平地强平了”。

**如何做**
1. RO 下令。RE 在 `/admin/risk-engine/liq` ≤2 分暂停。
2. 传播说真话：用户**仍可能有风险**；我们停机器人是因为尺子坏了。
3. **只有**标记新鲜 **且** RO 书面确认，才能恢复。

##### RE-03 标记价源切换

切到备源，然后看 PF-K01。**两个源都坏：** 只减仓和/或暂停强平。不要把两个烂数字平均一下就当没事。

##### RE-04 风险状态重建

风控余额和撮合/钱包对不上：先**冻结增险订单** → 从权威账本重建 → 抽样对账 → 再解冻。用户还能新开杠杆的时候不要重建。

##### RE-05 组合保证金模型变更

若统一账户/组合保证金已开：新模型先**并行影子跑** → 出缺口报告 → 特性开关 → 保留保守回退。双人 G01。Phase 1：通常关。

#### WA 钱包

**人话：** 币真正躺在这里。**热钱包** = 连着网，付提现，不能存超过缓冲。**冷钱包** = 更慢、更多人、有仪式。“补款”= 把币从冷搬到热，让真实提现还能付。“慢速模式”= 提现变慢，免得恐慌抽干热钱包。

##### WA-01 热钱包补款

**如何做**
1. 确认**链上**余额（不要只看内部屏）。*为什么：* 屏会滞后；链才是钱。
2. 黄灯：≤30 分启动冷→热。红灯：立刻启动。
3. 走密钥仪式（WA-05 / G04）。txid 记工单。确认缓冲真的回到政策以上。

##### WA-02 提现排队 / 慢速模式

**如何做**
1. 积压或挤兑风险红灯：≤15 分决定慢速模式。
2. 在 `/admin/wallet/withdraw` 打开。写下**优先级规则**（谁先拿到钱）和**退出标准**（缓冲 + 积压年龄）。
3. 状态页告知用户。藏起队列只会让挤兑更糟。

##### WA-03 链停 / 重组

**重组**是区块链改写最近几块。已经消失的块上的入账从来不是真的。暂停该链入账、量深度、若已入账则追回，按终局政策（要多少确认）再恢复。

##### WA-04 错充找回

用户发错资产、错链、或缺 memo。先核他是否拥有发送地址 → 能不能找回 → 费用政策 → **两个人**才能动资金 → 用 txid 关单。合规查反洗钱。这不是“退回去就行”。

##### WA-05 密钥仪式 / 轮换

至少两人（宜三人），写下仪式 ID，旧密钥销毁或登记作废。适用 G04。种子词拍照发聊天 = 事件。

##### WA-06 储备证明快照

选一个区块高度，提取负债，披露/鉴证，归档。按政策由 CRO/财务签。没有负债侧的截图不能当营销。

#### LD 上币 / 下币

**人话：** 上币 = 允许一个市场存在。下币 = 按**固定顺序**拿走它，免得代币没了现货价永续还开着，或我们正要关掉的币上还挂着贷款。

##### LD-01 上币风险意见

上币组做尽调包（谁发行、能不能冻账户、解锁、操纵史）。RO 写 **批准 / 有条件 / 驳回**。条件变成上线清单——不是客气建议。

##### LD-02 种子 / 监控标签

对客警告标签。可选收紧价格带。客服和传播必须和用户看到同一套标签。

##### LD-03 杠杆资格 `[Phase 2+]`

现货观察期平静后，信用风险才允许它当抵押 → 然后 MG-01。

##### LD-04 永续上线决定 `[Phase 1]`

需求 + 风险偏好 → RO 说准 → **PF-01**。Phase 1：这是活的上币路径（XAUUSD 及其他已批永续）。

##### LD-05 / LD-06 / LD-07 下币顺序

**强制顺序**（不能因为“现货才是正业”而跳）：
1. 风险 + 法务 + 合规批准。
2. **永续（LD-07）：** 只减仓 → 平掉或等到期 → 下线合约。
3. **杠杆（LD-06，Phase 2+）：** 冻借款 → 强制还款/强平 → 移出抵押。
4. **现货（LD-05，Phase 2+）：** 必要时停牌 → 关交易 → 提现按 WA。
5. 传播 + 客服话术。

##### LD-08 紧急下币 / 停牌

漏洞、欺诈、被盗增发。**安全优先：** 立刻停牌并禁充。24 小时内补手续。会同安全/合规取证。不要等一场体面的项目会。

#### CP 合规

**人话：** 合规决定*谁可以交易*、以及有没有人在**滥用**市场。风险决定*能加多少杠杆*。两份工作不要混。**硬冻结**是给交易、提现和/或杠杆上锁。

##### CP-01 监察告警分流

打开告警 → 判误报/属实 → 立案 → 挂上 UID 和产品。高严重度当天处理。你在建时间线，不是靠感觉。

##### CP-02 账户硬冻结

在 `/admin/compliance/holds` 上锁。告诉客服读哪份话术。**解除**冻结需要第二个人（G04）。加上可以快；拿掉才是危险方向。

##### CP-03 跨产品滥用复核

有人可能现货买、永续砸（或反过来）。跨产品做**一条**时间线。若在带动标记，告诉风险。按需冻结。

##### CP-04 监管协查 / 冻结

外部当局要求冻结。**先鉴别令函真伪**（伪造是存在的）。按载明范围冻、回函、留存。法务问责。不要为了“帮忙”扩大冻结范围。

#### TS / MM / ENG

##### TS-01 银行通道中断

银行或支付伙伴挂了。切到别的轨，和钱包/传播一起改充提文案；若造成流动性空洞则告诉风险。完成 = 原通道或备通道真的活着。

##### TS-02 稳定币脱锚响应

“1 美元的币”不再是 1 美元。先确认是**外盘**真脱锚（S3）还是我们预言机错了（S2）。库存与兑付，折扣/借款走 MG-03 `[Phase 2+]`，传播。硬脱锚 → L3。

##### TS-03 日终对账后结算

**只有** `SettlementReady`（G05）之后才打款。附银行/txid。重大差异还开着就结算 = 可能打两遍钱。

##### TS-04 保险基金注资

RM-06 + CRO 之后把公司的钱打进保险池。双控（G04）。入账。告诉风险。这不是钱包里无声的漂移。

##### MM-01 SLA 违约催办

做市商答应在买卖两边都挂单。深度/价差挂了（SP-K01/02），就打电话、执行合同；簿乱则请风险考虑停牌。

##### MM-02 波动市扩价

风暴里他们可以按协议扩价，但必须有**心跳**（报价还在更新）。静默空簿是停机（S5），不是“波动”。

##### MM-03 信息隔离检查

若有关联自营台，不能看见客户流向。上币或出现自营重叠时把检查记下来。

##### ENG-01 特权后台赋权

入职/转岗：最小权限、限时、有工单、每季再认证。BU PIC + 安全都要签。本手册里的后台页是危险的；权限不是纪念品。

##### ENG-02 审计日志不可篡改抽查

定期证明没人能改历史。缺口 = L3——法庭记录丢了。

##### ENG-03 管道延迟事件

风险数字晚了（PL-K06）。修消费者。若标记不安全，**先**触发 RE-02 / PF-03，再去写完 Kubernetes 工单。完成 = 延迟回到黄灯以下。

##### ENG-04 安全事件（密钥 / API）

密钥失陷：**≤2 分杀掉**，轮换，通知，取证，L3/L4 战时。告知 CRO/CISO/合规。速度比完美报告重要。

#### ACCESS — Phase 1 V-Exchange 开户 `[Phase 1]`

**人话：** Phase 1 不能从官网自己注册。**2C** 终端用户经**经纪商**进入（Vantage 或其他子品牌，或外部白标 / API 经纪商）。**对冲基金 / 高净值**走**线下开户、仅 API**。**做市商**走流动性接入。KYC 之后拿到 **永续账户**，入金只允许 **USD/USDT**。现货、USD 杠杆、跨币种保证金、组合保证金、期权、理财开关保持关。若发现公众“注册”按钮是开的，那是 **L3 事件**，不是增长业绩。

##### ACC-01 经纪商 / 子品牌 2C 开户

| 字段 | 明细 |
|------|------|
| **何时** | 已签约经纪商（Vantage 子品牌或外部白标 / API）引入一名终端用户 |
| **谁** | **R：** 经纪商运营 / 产品 · **A 合规：** KYC/KYB 门禁 · **A 风险权益：** RO · **R 打开交易：** RE/ENG 标志 |
| **SLA** | 经纪商标签绑定：合规放行后自动 ≤5 分 · 人工合规按政策 · 放行后权益推送 ≤15 分 |
| **前置** | Phase 1 模式开；经纪商协议有效；制裁筛查通过 |
| **系统** | 经纪商门户 · KYC · `/admin/compliance/holds` · 风险限额档 |

**如何做（每步为什么）**
1. **确认经纪商协议仍有效**（没过期、没被暂停）。*为什么：* 失效经纪商不是正门。
2. **收集 KYC/KYB**（他是谁；若是公司，谁拥有）。
3. **合规放行。** 在此之前账户只是一个文件夹，不是交易员。
4. **绑定元数据：** 经纪商 id、子品牌 vs 外部白标、谁引入、何时。*为什么：* 以后监察和经纪商分润都靠这个标签。
5. **先开户，再开永续账户。** 产品权益 = **仅永续**。现货 / 杠杆 / 期权 / 理财标志 **关**。
6. **入金规则：** 只允许从 **MT 账户** 或 **X-fund** 向永续账户划转 **USD/USDT**。
7. 打开交易开关。写审计日志。抽查：能开已批永续吗？**不能**开出现货单吗？

**完成：** 只能交易已批永续，并挂在该经纪商下。**升级：** 发现公众注册入口开着 → **先 L3 关掉入口**，再清已经放出的 UID。

##### ACC-02 机构直连（线下，仅 API）

**这份 SOP 干什么：** 对冲基金或高净值在 V-Exchange **线下开户**，只拿 **API**——没有公众界面注册。限额取（机构簿限额，账户限额）里**更严**的那个。

**如何做**
1. 线下 KYC/KYB 包齐；法务/合规给实体定性。
2. **不走零售 UI** 开户。API 密钥走双控（G04）。
3. 两套限额都套上；引擎必须用更严的。
4. 权益 = Phase 1 **永续账户** only（USD/USDT）。VIP/授信走双控。
5. 协议失效：先**杀掉新 API 密钥**。已有仓位按协议 + 风险意见处理。

**完成：** 机构只走批准的 API 路径交易；监察能把订单归因到该法律实体。

##### ACC-03 Phase 1 权益与通道护栏（每天）

**这份 SOP 干什么：** 每天问一次“大门还锁着吗，钱还在绿色通道上吗”。

**如何做**
1. 任何 UID 被打开现货、USD 杠杆、跨币种保证金、组合保证金、期权或理财 → 告警。
2. 自助 2C 注册若开着 → 告警。
3. 没有经纪商、机构、做市商标签却能下单 → 告警。
4. 永续账户收下了**不是** USD/USDT 的划转 → 告警。
5. 日报给 RO-OPS + 合规。零例外，或例外必须挂**阶段门禁豁免**工单（不是 Slack 一个表情）。

**完成：** 每日零例外，或每条例外都有豁免工单。

##### ACC-04 做市商 / 流动性伙伴接入

**这份 SOP 干什么：** 已签约做市商接入 V-Exchange，为 Phase 1 永续报价。他们是 2B，不是零售 2C。

**如何做**
1. 协议 + 做市 SLA 有效（心跳、该永续簿的最大价差/深度）。
2. 线下开户；打 **MM** 标签。API 密钥双控。
3. 权益 = 仅永续。若有关联自营台，走信息隔离（MM-03）。
4. 心跳死了 → 按情景族 **S5**（单标的流动性空洞）处理，不要当成“他们安静了”。

**完成：** MM 标签 + SLA 监控已挂到他们覆盖的标的。

## 8. 限额、KRI、阈值、动作与升级

### 8.1 读法

这一章是**值班观察清单**。每一行是一只传感器。你不必背公式，但要知道：它在量什么、什么叫“有点不对”、什么叫“坏了”、机器已经做了什么、人还必须做什么。

| 列 | 人话 |
|----|------|
| **ID** | 稳定编码（如 PF-K01），贴进工单和看板，大家指同一只传感器 |
| **指标** | 用话说清楚在量什么 |
| **频率** | 多久看一次（每秒还是每天） |
| **WARN（黄）** | 软阈：要调查，通常不自动阻断。像发动机故障灯 |
| **BREACH（红）** | 硬阈：必须有动作（系统及/或人）。像刹车 |
| **自动动作** | 不等你、系统已做的（仅在安全时） |
| **人工动作** | 即使系统已动，你仍必须做的 |
| **升级** | 按 §8.2 的 L1–L4 呼叫谁 |
| **主责** | 哪个 BU 对响应质量负责 |

**确认 SLA（RO-OPS）：** WARN ≤15 分 · BREACH ≤5 分 · Kill/客户资产 ≤2 分。确认 = “我看见了”，不是“修好了”。  
阈值变更走 SOP-G01；标 *calib.* 须换成《限额手册》真值。

**Phase 1 日报习惯：** 先看 **永续 PF-K\*** 和 **准入 ACC/平台**。现货 SP-K\*、杠杆 MG-K\* 留在表里供预习，Phase 2+ 前视为休眠。

### 8.2 升级阶梯

升级不是“谁职级更高”，而是“爆炸半径有多大、必须多快把人拉进电话”。

若两档之间拿不准，**选高的那档**并说出来。允许事后降级；不允许该叫而没叫。

| 级别 | 标准 | 通知 | 建桥时限 |
|------|------|------|----------|
| **L1** | 单笔 WARN；疑似数据质量；无客户影响 | RO-OPS | 工单即可 |
| **L2** | 硬突破且限于 1 标的/账户类；可逆 | RO + BU PIC（引擎相关含 RE） | 15 分 |
| **L3** | 多标的连环、保险动用、ADL 风暴、长时间停牌 | CRO + 产品 PIC + ME + RE + 传播 | 立即 |
| **L4** | 客户资金威胁、密钥/API 失陷、全站停牌、大范围错价 | ELT · 危机传播 · 法务 · 合规 · CISO | 立即+高管桥 |


**图 — 升级阶梯**

```mermaid
  L2 --> L3["L3 CRO + ME + RE + 传播"]

```

### 8.3 限额类型

限额不是“感觉今天该紧一点”，而是写在《限额手册》里的政策选择。三种要分清：

| 类型 | 人话 | 例子 |
|------|------|------|
| 软（WARN） | 早警告；默认不自动阻断。你仍须确认。 | 永续持仓量 ≥ 上限的 80% |
| 硬（BREACH） | 系统及/或人*必须*行动。 | 用户杠杆超过其档位 → 拒单 |
| Kill | 立刻停机。永远两个人。 | 撮合总闸；提现冻结 |

软还是硬，以《限额手册》为准，不以当天心情为准。

### 8.10 告警状态机

把告警想成一条流水线，不要从中间跳进去：

1. **检测** — 系统算出一只灯该黄或该红。  
2. **路由** — WARN / BREACH / KILL 走不同 SLA。  
3. **确认** — 人在 SLA 内点“我看见了”。  
4. **数据质量？** — 时间戳陈旧则修管道（ENG-03），不要拿陈旧数字去强平或停牌。  
5. **真风险** — 核对应自动动作打没打出。  
6. **人工遏制** — 按产品 SOP（永续 PF-* 等）。  
7. **超时** — 升 L+1，自动叫下一个人。  
8. **超护** — 遏制之后还要盯，通常 24 小时。  
9. **复盘** — Sev-1/2 五个工作日内，趁还记得。

**默认处理时限：** 黄灯 30–60 分还没方案；红灯 15 分；Kill/客户资产 = 立刻 L3/L4；超护 24h；复盘 5 个工作日。

### 9.3 单指标情景（绿/黄/红可能原因）

#### 现货 SP-K01 价差
- **绿：** 正常做市；低波。同伴深度、时延亦绿。  
- **假绿：** 中间价计算坏（空簿 NaN→0）；错误最小变动价。  
- **黄：** MM 主动扩价；波动抬升；库存偏斜；单边流；部分 MM 故障。  
- **红：** MM 全断；失序市；残停牌；API 限频饿死 MM。  
**时序：** `波动↑ → 黄价差 → 黄深度`（市场）· `MM 进程崩 → 秒级红深度再红价差`（技术）。

#### 现货 SP-K03 偏离
- **绿：** 价格发现一致且源新鲜。  
- **假绿：** 参考源与最新价一起卡住。  
- **黄：** 瞬时失衡、套利滞后、新闻微缺口、薄山寨。  
- **红：** 预言机/参考 bug、操纵成交、符号映射错、仅参考所停牌、成分失效。  
**时序：** `外盘崩 ≈ 红`（真跌）· `外盘平而本地红`（本地簿/操纵/数据）。

#### 现货 SP-K09 时延
- **黄：** 负载、GC、撤单风暴初起。  
- **红：** 分片过载、网络分区、坏发布、无限撤单环、DDoS。  
**时序：** `SP-K04 黄 → SP-K09 黄→红`（撤单风暴）· `发布 → 单独红时延`（坏版本）。

#### 杠杆 MG-K01 借款占用
- **黄：** 真实需求、轧空萌芽、出借人撤资。  
- **红：** 轧空、可借资产挤兑、库存分母配错、巨鲸借入。  
**时序：** `现货暴跌 → 补保 → 抢借稳定币 → 占用黄/红`。

#### 杠杆 MG-K02 近强平
- **红但无强平单：** 引擎卡住 — **L3 级严重**。  
**健康时序：** `价格冲击 → MG-K02 红 → MG-K03 强平量↑`。  
**病态：** `MG-K02 红 ↛ MG-K03` 超过 15–30 秒。

#### 杠杆 MG-K04 坏账 / MG-K08 脱锚
- 脱锚真时序：`外盘脱锚 ≈ MG-K08 → MG-K02/03 → MG-K04`。  
- `MG-K08 红而链上+外盘仍绿` → 本地标记 bug（归 S2 子类）。

#### 永续 PF-K01 / PF-K06 / PF-K07–08
- **PF-K01 红：** 指数坏、标记公式 bug、用最新价被操纵、熔断未触发。  
- **经典连环：** `宏观下跌 → PF-K01 黄 → PF-K06 黄→红 → PF-K07 黄`。  
- **`PF-K06 红 + 标的平坦`：** 错标记/bug — Sev-1 候选。  
- **`PF-K08 早于 PF-K07 黄`：** ADL 触发配错，非自然耗尽。

#### 平台 PL-K01/02 / PL-K06 / PL-K05
- `利空 → 提现浪 → PL-K01→02`（挤兑）。  
- `PL-K02 红而 PL-K01 绿`：签名/链瓶颈非余额。  
- `PL-K06 红领先 → 多 KRI 变色但外盘未动`：数据事件（S2）。

#### 当“绿”本身异常
大跌而 PF-K01/SP-K03 仍绿 → 源冻结/规则关闭/阈值过松；  
MG-K02 全绿却 MG-K03 飙升 → 可能强平错户/测试流量；  
危机中全绿 → 看板指到预发环境或缓存快照（S9）。

**战时常设角色：** 事件指挥官 · 风险 · 撮合 · 风控引擎 · 钱包 · 传播 · 合规 · 记录员  

**必须记录：** 时间线（§9 时钟）、改过的配置、期间订单/强平、采纳的情景族（S1–S12）、客户影响、永久修复负责人。  

**情景→定级提示：** S2 大规模错强平 · 带 PL-K08 的 S8 · 危机中 S9 → 先按 **Sev-1**；S5 单币 MM → 常 Sev-3；S1 有序抛售且保险仍绿 → Sev-2/3 运维模式。

### 11.1 术语

更多白话解释见 [零基础说明](#零基础说明)。

| 术语 | 人话 |
|------|------|
| 标记价 Mark | 永续用来算盈亏和“该不该强平”的公允价，不是最新成交 |
| 指数价 Index | 多家外盘价格合成，用来做标记 |
| 资金费率 Funding | 多空之间定期付钱，让永续不要永远偏离真价 |
| ADL | 保险填不起强平窟窿时，从盈利的对手仓上减仓 |
| LTV | 贷款相对抵押值的比例（杠杆借贷） |
| STP | 自成交防护，防止自己和自己成交刷量 |
| 保险基金 | 强制平仓仍留下未付亏损时用来填的池子 |
| 只减仓 Reduce-only | 只允许把仓变小、不许变大的订单 |
| A+ 级 | 大到必须两个人批（四眼）的变更 |
| RAG | 红 / 黄 / 绿 指标状态（§9） |
| 情景族 | 多只 KRI 按某种顺序一起动的命名模式 S1–S12 |
| Phase 1 | 现在生产：V-Exchange 永续（含 XAUUSD）；永续账户（USD/USDT）；撮合 / 风控 / 清结算。准入 = 经纪商 / 机构 / 做市；2C 经经纪商。 |
| Phase 2+ | 写在手册里但开关是关的（现货、USD 杠杆、跨币种保证金、组合保证金、期权、理财、公众 2C 注册） |
| V-Exchange | Finprime 场所（ADGM / 毛里求斯）。撮合 + 清结算 + 风控。 |
| 永续账户 Perp Account | Phase 1 交易账户。只允许划入 USD/USDT。 |
| MT 账户 / X-fund | 入金钱包。用户先入金到这里，再把 USD/USDT 划进永续账户。 |
| 2B / 2C | 对公 vs 对客。2C 经经纪商进入。2B = 经纪商、机构（仅 API）、做市商。 |
| 经纪商通道 | Vantage 子品牌或外部白标 / API 经纪商。线下开经纪商。 |
| KYC | 交易前的身份核验 |
| 抵押 / 保证金 | 客户押上的资产，赌错了用来平仓 |
| 强平 | 抵押不够时强制平掉仓位 |
| 名义 Notional | 用钱衡量的仓位大小 |
| 持仓量 OI | 未平永续仓的合计，有上限防止过度拥挤 |
| 基差 Basis | 永续价与指数/现货的差 |
| 折扣 Haircut | 因为抵押可能还没卖掉就先跌，所以先打个折 |
| 超护 Hypercare | 变更后加盯的时间窗 |
| 限额手册 Limit Book | 签过字的真 WARN/BREACH 数字；本手册数字是例子 |
| 四眼 / Maker–Checker | 两个人：一个提、一个批 |
| 破窗 | 限时紧急权限，永远带工单 |
| 战时指挥 | 有座位名单的电话：指挥官、风险、撮合、引擎、钱包、传播、合规、记录员 |
