<h2 id="1-what-this-desk-is" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">1. What this desk is</h2>

<p class="text-sm leading-relaxed my-2">Vantage <strong>CRMP Admin</strong> is the control room for CFD and crypto risk. Monitor 2.0 raises an alarm. This desk then:</p>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Finds a matching skill playbook, or searches the RAG knowledge base if no skill is certain.  </li>
<li>On high severity (BREACH or CRITICAL), runs a <strong>second, independent AI</strong> that may agree, partly agree, or disagree.  </li>
<li>Puts the pack into a <strong>Lark-style messenger</strong> so you can show evidence, chat, escalate, dismiss, close, or send a control.  </li>
<li>Asks a human checker before irreversible controls go live.  </li>
<li>Writes the whole story into the <strong>Spine Log</strong> and <strong>Audit Log</strong>.</li>
</ol>

<p class="text-sm leading-relaxed my-2">You do not need to be an engineer to use it. Click the left menu, read the cards, and follow the buttons on the page.</p>

<p class="text-sm leading-relaxed my-2"><strong>Permanent public demo:</strong> <a class="underline" href="https://hxyan2020.github.io/PRD/crmp-admin/admin/">https://hxyan2020.github.io/PRD/crmp-admin/admin/</a>  </p>
<p class="text-sm leading-relaxed my-2"><strong>Messenger demo:</strong> <a class="underline" href="https://hxyan2020.github.io/PRD/crmp-admin/admin/messenger/">https://hxyan2020.github.io/PRD/crmp-admin/admin/messenger/</a>  </p>
<p class="text-sm leading-relaxed my-2"><strong>Full URL list:</strong> <a class="underline" href="/admin/docs/urls">URL Catalog</a></p>

<p class="text-sm leading-relaxed my-2">On GitHub Pages there is <strong>no live <code class="rounded bg-slate-100 px-1 text-[0.9em]">/api</code></strong>. You can still walk every screen. Buttons that would save to the server keep a copy in this browser instead. Live writes (real scans, dual-control applies, user create) belong on <code class="rounded bg-slate-100 px-1 text-[0.9em]">localhost:3000</code>.</p>

<h3 id="2-3-language" class="text-lg font-semibold mt-6 mb-2">2.3 Language</h3>

<p class="text-sm leading-relaxed my-2">Use <strong>EN / 繁中</strong> (sidebar on desktop; header on a phone). The choice is stored in the <code class="rounded bg-slate-100 px-1 text-[0.9em]">crmp_ui_lang</code> cookie. Every left-nav label, page title, and product doc can switch. Open a doc with <code class="rounded bg-slate-100 px-1 text-[0.9em]">?lang=zh-Hant</code> if you want to share a Chinese link.</p>

<h3 id="2-4-phones" class="text-lg font-semibold mt-6 mb-2">2.4 Phones</h3>

<p class="text-sm leading-relaxed my-2">Tap the <strong>hamburger</strong> (Menu) to open the left nav. Messenger is list-first: tap a thread, then <strong>Threads</strong> to go back. Language sits in the header.</p>

<h3 id="2-5-selection-ai-chatbot" class="text-lg font-semibold mt-6 mb-2">2.5 Selection AI chatbot</h3>

<p class="text-sm leading-relaxed my-2">On any admin page, <strong>select text</strong> (or long-press on a phone). A teal sparkle icon appears next to the highlight. Tap it: a chat drawer explains that passage in this CRMP’s terms (Monitor vs mock Lark, EXECUTED_MOCK, who can approve, which page to open). You can keep asking follow-ups. It is read-only — it cannot approve an intervention or change settings. On GitHub Pages it uses the same grounded glossary (no live LLM required).</p>

<h2 id="4-what-each-role-does-every-day" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">4. What each role does every day</h2>

<h3 id="risk-owner" class="text-lg font-semibold mt-6 mb-2">Risk Owner</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Open <a class="underline" href="/admin/alerts">Live Alerts</a> and <a class="underline" href="/admin/ai-analyses">AI Analyses</a>. Look for BREACH / CRITICAL.  </li>
<li>Open the dual-AI pack. If the second AI is <code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code> or <code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code>, do <strong>not</strong> approve an irreversible control yet.  </li>
<li>In <a class="underline" href="/admin/messenger">Demo Messenger</a>: escalate, <strong>Close (accept AI)</strong>, or <strong>Dismiss</strong> a false alarm.  </li>
<li>On <a class="underline" href="/admin/interventions">Human Intervention</a>, approve checker steps after Ops has maker-confirmed a control.  </li>
<li>Run the <a class="underline" href="/admin/docs/uat">UAT Checklist</a> when you sign off a release.</li>
</ol>

<h3 id="risk-analyst" class="text-lg font-semibold mt-6 mb-2">Risk Analyst</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Work the OPEN queue on Live Alerts.  </li>
<li>Open the AI analysis. Read summary, evidence, and second-AI verdict.  </li>
<li>In messenger, <strong>Show evidence</strong>, then type in <strong>Chatbot</strong> if you disagree or have extra context.  </li>
<li>Escalate to Risk Owner when the pack is ready.</li>
</ol>

<h3 id="ops-lead-analyst" class="text-lg font-semibold mt-6 mb-2">Ops Lead / Analyst</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>From messenger <strong>Recommended actions</strong>, pick block / halt / cut leverage / pre-widen / pause-copy.  </li>
<li>Click <strong>Double-confirm…</strong> then <strong>Yes, send to Vantage admin</strong>. You get an admin reference and a link.  </li>
<li>If the thread says checker is needed, wait for Risk Owner on Human Intervention.</li>
</ol>

<h3 id="ai-engineer" class="text-lg font-semibold mt-6 mb-2">AI Engineer</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Keep <a class="underline" href="/admin/skills">AI Skills</a>, <a class="underline" href="/admin/rag">RAG</a>, and <a class="underline" href="/admin/detectors">Detectors</a> healthy.  </li>
<li>Propose setting/model/skill/RAG changes on <a class="underline" href="/admin/ai-admin">AI Admin</a>. You cannot approve your own change.  </li>
<li>Tune <code class="rounded bg-slate-100 px-1 text-[0.9em]">ai.second_opinion_severity</code> (default BREACH) under AI Admin parameters or Platform Settings.</li>
</ol>

<h3 id="system-admin" class="text-lg font-semibold mt-6 mb-2">System Admin</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Users, roles, teams, departments, grouped settings.  </li>
<li>Review <a class="underline" href="/admin/security/ai-access">AI Access Security</a> — pages, functions and fields AI must never touch.  </li>
<li>Watch <a class="underline" href="/admin/audit">Audit Log</a> and <a class="underline" href="/admin/spine">Spine Log</a>.</li>
</ol>

<h2 id="5-the-main-story-alarm-ai-chat-close" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">5. The main story: alarm → AI → chat → close</h2>

<p class="text-sm leading-relaxed my-2">This is the path you will use most. Later sections explain every other page.</p>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>A detector or Monitor 2.0 indicator breaches.  </li>
<li>An <strong>OPEN</strong> alert appears on Live Alerts (and a ticket on Monitor 2.0).  </li>
<li>AI Analyses gets a pack: <code class="rounded bg-slate-100 px-1 text-[0.9em]">SKILL_MATCH</code> if a playbook fits, otherwise <code class="rounded bg-slate-100 px-1 text-[0.9em]">RAG_REASONING</code>.  </li>
<li>If severity is BREACH or CRITICAL, a <strong>Second AI</strong> panel appears (<code class="rounded bg-slate-100 px-1 text-[0.9em]">AGREE</code> / <code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code> / <code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code>).  </li>
<li>Click <strong>Sync alerts</strong> on Demo Messenger so the pack is a chat thread.  </li>
<li><strong>Show evidence</strong> posts the vault into the thread. Chat if you challenge the story.  </li>
<li><strong>Escalate</strong>, <strong>Dismiss</strong> (false alarm), or <strong>Close (accept AI)</strong>.  </li>
<li>For a control: pick a recommended action → double-confirm → checker if required.  </li>
<li>Confirm the same events in Spine Log and Audit Log.</li>
</ol>

<p class="text-sm leading-relaxed my-2"><strong>Demo shortcuts on AI Analyses</strong> (localhost): Simulate COPY breach (skill path), Simulate EQ drawdown (RAG, often WARN so second AI is skipped), Simulate CRITICAL (forces second AI), Backfill 2nd AI challenges.</p>

<p class="text-sm leading-relaxed my-2"><strong>Decision rule:</strong> <code class="rounded bg-slate-100 px-1 text-[0.9em]">AGREE</code> may follow the playbook under policy. <code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code> / <code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code> means <strong>needs human</strong> — no irreversible control until a person has read both AIs.</p>

<li>高嚴重度（BREACH 或 CRITICAL）時，再跑一輪<strong>獨立的第二 AI</strong>，可能同意、部分同意或不同意。  </li>
<li>把整包放進 <strong>Lark 風格 Messenger</strong>，讓你顯示證據、聊天、升級、排除、結案或送出控制。  </li>
<li>不可逆控制上線前，要有人類 Checker。  </li>
<li>整段故事寫進<strong>脊柱日誌</strong>與<strong>稽核日誌</strong>。</li>
</ol>

<p class="text-sm leading-relaxed my-2">不必是工程師。點左側選單、讀卡片、跟畫面上的按鈕走即可。</p>

<h3 id="風險負責人" class="text-lg font-semibold mt-6 mb-2">風險負責人</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>打開 <a class="underline" href="/admin/alerts">即時警報</a> 與 <a class="underline" href="/admin/ai-analyses">AI 分析</a>，找 BREACH／CRITICAL。  </li>
<li>打開雙 AI 包。若第二 AI 是 <code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code> 或 <code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code>，<strong>先不要</strong>核准不可逆控制。  </li>
<li>在 <a class="underline" href="/admin/messenger">示範 Messenger</a> 升級、<strong>結案（接受 AI）</strong>，或 <strong>排除</strong> 誤報。  </li>
<li>Ops 已 Maker 確認控制後，到 <a class="underline" href="/admin/interventions">人工干預</a> 做 Checker。  </li>
<li>版本驗收時跑 <a class="underline" href="/admin/docs/uat">UAT 清單</a>。</li>
</ol>

<h3 id="風險分析師" class="text-lg font-semibold mt-6 mb-2">風險分析師</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>處理即時警報的 OPEN 佇列。  </li>
<li>打開 AI 分析，讀摘要、證據、第二 AI 結論。  </li>
<li>在 Messenger <strong>顯示證據</strong>，若不同意或有補充就打 <strong>聊天</strong>。  </li>
<li>包就緒後升級給風險負責人。</li>
</ol>

<h3 id="營運主管-分析師" class="text-lg font-semibold mt-6 mb-2">營運主管／分析師</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>從 Messenger <strong>建議動作</strong> 選封鎖／停交易／降槓桿／預先加寬／暫停跟單。  </li>
<li>點 <strong>雙重確認…</strong> 再 <strong>是，送至 Vantage 管理後台</strong>。會得到管理參照與連結。  </li>
<li>若執行緒說需要 Checker，等風險負責人在人工干預核准。</li>
</ol>

<h3 id="ai-工程師" class="text-lg font-semibold mt-6 mb-2">AI 工程師</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>維護 <a class="underline" href="/admin/skills">AI 技能</a>、<a class="underline" href="/admin/rag">RAG</a>、<a class="underline" href="/admin/detectors">偵測器</a>。  </li>
<li>在 <a class="underline" href="/admin/ai-admin">AI 管理</a> 提案設定／模型／技能／RAG。不能核准自己的變更。  </li>
<li>在 AI 管理參數或平台設定調整 <code class="rounded bg-slate-100 px-1 text-[0.9em]">ai.second_opinion_severity</code>（預設 BREACH）。</li>
</ol>

<h3 id="系統管理員" class="text-lg font-semibold mt-6 mb-2">系統管理員</h3>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>使用者、角色、團隊、部門、分組設定。  </li>
<li>檢視 <a class="underline" href="/admin/security/ai-access">AI 存取安全</a> — AI 絕不可碰的頁／功能／欄位。  </li>
<li>監看 <a class="underline" href="/admin/audit">稽核日誌</a> 與 <a class="underline" href="/admin/spine">脊柱日誌</a>。</li>
</ol>

<h2 id="5-主流程-警報-ai-聊天-結案" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">5. 主流程：警報 → AI → 聊天 → 結案</h2>

<p class="text-sm leading-relaxed my-2">這是最常用的路。後面章節再講其他頁。</p>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>偵測器或 Monitor 2.0 指標越線。  </li>
<li>即時警報出現 <strong>OPEN</strong>（Monitor 2.0 同時有工單）。  </li>
<li>AI 分析產生一包：劇本對得上就是 <code class="rounded bg-slate-100 px-1 text-[0.9em]">SKILL_MATCH</code>，否則 <code class="rounded bg-slate-100 px-1 text-[0.9em]">RAG_REASONING</code>。  </li>
<li>嚴重度是 BREACH 或 CRITICAL 時，出現 <strong>第二 AI</strong> 面板（<code class="rounded bg-slate-100 px-1 text-[0.9em]">AGREE</code>／<code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code>／<code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code>）。  </li>
<li>在示範 Messenger 點 <strong>同步警報</strong>，讓這包變成聊天執行緒。  </li>
<li><strong>顯示證據</strong> 把保險庫貼進對話。若要挑戰故事就聊天。  </li>
<li><strong>升級</strong>、<strong>排除</strong>（誤報）或 <strong>結案（接受 AI）</strong>。  </li>
<li>若要控制：選建議動作 → 雙重確認 → 必要時 Checker。  </li>
<li>到脊柱日誌與稽核日誌核對同一批事件。</li>
</ol>

<p class="text-sm leading-relaxed my-2"><strong>AI 分析頁的示範捷徑</strong>（localhost）：模擬 COPY 越線（技能路徑）、模擬 EQ 回撤（RAG，常為 WARN 故略過第二 AI）、模擬 CRITICAL（強制第二 AI）、回填第二 AI 挑戰。</p>

<p class="text-sm leading-relaxed my-2"><strong>決策規則：</strong> <code class="rounded bg-slate-100 px-1 text-[0.9em]">AGREE</code> 可依政策走劇本。<code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code>／<code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code> 代表 <strong>需要人類</strong> — 兩份 AI 都讀過之前，不要做不可逆控制。</p>

<li>部門分工。每張部門卡開啟該組工作頁（風險控管 → 即時警報、營運 → 人工干預、AI → AI 分析、系統 → 平台設定）。<strong>查看全部</strong> 開部門目錄。  </li>

<h2 id="7-監控與風險" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">7. 監控與風險</h2>

<h3 id="7-1-每日績效-admin-dashboard" class="text-lg font-semibold mt-6 mb-2">7.1 每日績效 — <code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/dashboard</code></h3>

<p class="text-sm leading-relaxed my-2"><strong>這頁是什麼。</strong> 當日結束的 CFD 與加密風險畫面 — 脊柱最後一環。</p>

<p class="text-sm leading-relaxed my-2"><strong>會看到什麼。</strong> 報表日、CFD／加密的 WARN／BREACH 數，以及指標卡（數值、目標、備註、健康）。</p>

<p class="text-sm leading-relaxed my-2"><strong>要點什麼。</strong> <strong>重新整理</strong>（localhost）會從 <code class="rounded bg-slate-100 px-1 text-[0.9em]">/api/dashboard</code> 重建即時指標。Pages 上是種子快照。</p>

<p class="text-sm leading-relaxed my-2"><strong>怎樣算正常。</strong> 兩個產品欄都在。狀態徽章可讀（HEALTHY／WARN／BREACH）。</p>

<h3 id="7-2-風險日誌分析-admin-risk-log" class="text-lg font-semibold mt-6 mb-2">7.2 風險日誌分析 — <code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/risk-log</code></h3>

<p class="text-sm leading-relaxed my-2"><strong>這頁是什麼。</strong> 歷史帳：什麼觸發、人處理多久、損失 vs 防損金額、漏洞集中在哪。</p>

<p class="text-sm leading-relaxed my-2"><strong>會看到什麼。</strong></p>

<ul class="list-disc pl-5 my-2 space-y-1 text-sm">
<li>摘要磚：未結警報、損失 vs 防損 vs 曝險、平均確認／結案／人工分鐘、SLA 逾時、待決 vs 已決干預。  </li>
<li>依類別、依領域的表。  </li>
<li>漏洞標籤（反覆弱點）。  </li>
<li>時序紀錄（警報、工單、結果、美元）。</li>
</ul>

<p class="text-sm leading-relaxed my-2"><strong>要點什麼。</strong> 篩選／掃表。需要整包時跟列回到即時警報或 AI 分析。</p>

<p class="text-sm leading-relaxed my-2"><strong>怎樣算正常。</strong> 合計對得上。已結案件有處理時間。示範種子的漏洞標籤不是空的。</p>

<h3 id="7-3-市場情報-admin-market-intel" class="text-lg font-semibold mt-6 mb-2">7.3 市場情報 — <code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/market-intel</code></h3>

<p class="text-sm leading-relaxed my-2"><strong>這頁是什麼。</strong> 每五分鐘看新聞、社群、官方與交易所貼文，找出可能移動 LP 報價的訊息。發現餵給指標 <code class="rounded bg-slate-100 px-1 text-[0.9em]">M2-MKT-INTEL</code> 與 Messenger 寄件匣（正式環境 Lark 群 <code class="rounded bg-slate-100 px-1 text-[0.9em]">oc_market_intelligence</code>）。</p>

<p class="text-sm leading-relaxed my-2"><strong>會看到什麼。</strong> 分頁：<strong>發現</strong>、<strong>Messenger 寄件匣</strong>、<strong>來源</strong>、<strong>掃描紀錄</strong>。卡片用 i–vi 格式（發生什麼、產品、為何可能移動 LP、嚴重度、來源、建議下一步）。排程開／關。技能劇本連結。</p>

<p class="text-sm leading-relaxed my-2"><strong>要點什麼。</strong></p>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>若畫面閒置，先在平台設定打開 <code class="rounded bg-slate-100 px-1 text-[0.9em]">market_intel.enabled</code>。  </li>
<li>點 <strong>立即掃描</strong>。  </li>
<li>讀新發現，再看出件匣，再看掃描紀錄。</li>
</ol>

<p class="text-sm leading-relaxed my-2"><strong>GitHub Pages：</strong> 沒有 <code class="rounded bg-slate-100 px-1 text-[0.9em]">/api</code>，所以 <strong>立即掃描</strong> 會跑<strong>本機示範掃描</strong>（與正式掃描同一批事件模板）。新卡片立刻出現，存在這個瀏覽器（<code class="rounded bg-slate-100 px-1 text-[0.9em]">crmp_mi_demo_v1</code>）。真正 HTTP 抓取仍屬 <code class="rounded bg-slate-100 px-1 text-[0.9em]">localhost:3000</code>。<strong>不會</strong>出現 405。</p>

<h2 id="10-組織" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">10. 組織</h2>

<h3 id="10-1-部門-admin-departments" class="text-lg font-semibold mt-6 mb-2">10.1 部門 — <code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/departments</code></h3>

<p class="text-sm leading-relaxed my-2">風險控管、營運、AI、系統的卡片：說明、團隊數、使用者數、主要職責（RACI）。唯讀目錄。</p>

<h3 id="10-2-團隊-admin-teams" class="text-lg font-semibold mt-6 mb-2">10.2 團隊 — <code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/teams</code></h3>

<p class="text-sm leading-relaxed my-2">表：團隊名、部門、成員、Lark chat id、值班輪值、任務。路徑開火時叫醒的就是這些人。</p>

<h3 id="10-3-角色與權限-admin-roles" class="text-lg font-semibold mt-6 mb-2">10.3 角色與權限 — <code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/roles</code></h3>

<p class="text-sm leading-relaxed my-2">每個角色（風險負責人、分析師、營運、AI 工程師、系統管理員、超級管理員、檢視者…）及其權限晶片（<code class="rounded bg-slate-100 px-1 text-[0.9em]">monitor.read</code>、<code class="rounded bg-slate-100 px-1 text-[0.9em]">ai.approve</code>、<code class="rounded bg-slate-100 px-1 text-[0.9em]">settings.manage</code>…）。超級管理員有 <code class="rounded bg-slate-100 px-1 text-[0.9em]">*</code>。用這頁理解某個角色為什麼少一顆按鈕。</p>

<h3 id="10-4-使用者-admin-users" class="text-lg font-semibold mt-6 mb-2">10.4 使用者 — <code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/users</code></h3>

<p class="text-sm leading-relaxed my-2">操作員與示範角色目錄，含 <strong>demo platform owner</strong>。欄位：姓名、email、角色、部門、團隊、狀態、上次登入。</p>

<p class="text-sm leading-relaxed my-2">有 <code class="rounded bg-slate-100 px-1 text-[0.9em]">users.manage</code>（localhost）可 <strong>新增使用者</strong>（姓名、email、密碼、角色、部門、團隊）並切換 ACTIVE／DISABLED。Pages 上新增多半是示範空操作或僅本機瀏覽器。</p>

<p class="text-sm leading-relaxed my-2"><strong>怎樣算正常。</strong> demo platform owner 以平台負責人存在。停用使用者在 localhost API 不能當即時 Maker／Checker。</p>

<p class="text-sm leading-relaxed my-2"><strong>怎樣算正常。</strong> 核准路徑、使用者／角色寫入、交易執行都在黑名單。允許清單很窄（讀證據、起草 RCA、檢索 RAG）。</p>

<h2 id="13-每次都要做的安全習慣" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">13. 每次都要做的安全習慣</h2>

<li>把 Messenger <strong>排除</strong> 與 <strong>結案</strong> 當真正決策 — 會被稽核。  </li>
<li>BREACH／CRITICAL 時，不可逆控制前主 AI 與第二 AI 都要留在畫面上。  </li>
<li>控制之後，用同一組 id 核對 <strong>稽核日誌</strong> 與 <strong>脊柱日誌</strong>。  </li>
<li>AI 管理與指定控制的 Maker 與 Checker 必須是<strong>兩個人</strong>。</li>
</ol>
