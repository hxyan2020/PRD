<h2 id="1-problem-statement" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">1. Problem statement</h2>

<p class="text-sm leading-relaxed my-2">Vantage Markets operates CFD and crypto risk across Monitor 2.0 indicators, desks, and messenger escalation. Today, alarm → root cause → action is fragmented: analysts re-derive context, AI suggestions (if any) lack an independent challenge, and irreversible controls are hard to audit end-to-end.</p>

<p class="text-sm leading-relaxed my-2"><strong>We need a centralised risk management plane that:</strong></p>
<ul class="list-disc pl-5 my-2 space-y-1 text-sm">
<li>Turns Monitor alarms into explainable AI RCA  </li>
<li>Challenges high-severity RCA with a second independent AI  </li>
<li>Lets operators act in messenger (evidence, escalate, dismiss, close, controls)  </li>
<li>Enforces maker/checker and keeps AI off human-only surfaces  </li>
<li>Leaves a single spine + audit trail  </li>
</ul>

<h2 id="5-user-journeys-happy-path" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">5. User journeys (happy path)</h2>

<h3 id="5-1-high-severity-alarm-dual-ai-messenger-close" class="text-lg font-semibold mt-6 mb-2">5.1 High-severity alarm → dual-AI → messenger close</h3>
<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Monitor indicator breaches (e.g. COPY concentration).  </li>
<li>CRMP creates alert + AI analysis (<code class="rounded bg-slate-100 px-1 text-[0.9em]">SKILL_MATCH</code> or <code class="rounded bg-slate-100 px-1 text-[0.9em]">RAG_REASONING</code>).  </li>
<li>If severity ≥ <code class="rounded bg-slate-100 px-1 text-[0.9em]">ai.second_opinion_severity</code> (default BREACH), run <code class="rounded bg-slate-100 px-1 text-[0.9em]">crmp-challenger-v0</code>.  </li>
<li>Risk Analyst opens Demo Messenger thread; <strong>Show evidence</strong>; optionally challenges via chatbot.  </li>
<li>Risk Owner reviews primary + challenger; <strong>Close (accept AI)</strong> or escalates / requests control.</li>
</ol>

<h3 id="5-2-control-with-double-confirm-checker" class="text-lg font-semibold mt-6 mb-2">5.2 Control with double confirm + checker</h3>
<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Operator selects recommended action (e.g. Block user account).  </li>
<li>Double-confirm gate → mock Vantage admin ref + link.  </li>
<li>If <code class="rounded bg-slate-100 px-1 text-[0.9em]">needs_checker</code>, Checker approves via Interventions / instructed path.  </li>
<li>Audit + Spine record maker/checker outcome.</li>
</ol>

<h3 id="5-3-ai-admin-change" class="text-lg font-semibold mt-6 mb-2">5.3 AI Admin change</h3>
<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Maker proposes setting/model/policy in AI Admin.  </li>
<li>Distinct Checker approves.  </li>
<li>Self-approve is rejected.</li>
</ol>

<h2 id="5-使用者旅程-快樂路徑" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">5. 使用者旅程（快樂路徑）</h2>

<h3 id="5-1-高嚴重度警報-雙-ai-messenger-結案" class="text-lg font-semibold mt-6 mb-2">5.1 高嚴重度警報 → 雙 AI → messenger 結案</h3>
<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Monitor 指標觸發（如跟單集中度）。  </li>
<li>CRMP 建立警報＋AI 分析（<code class="rounded bg-slate-100 px-1 text-[0.9em]">SKILL_MATCH</code> 或 <code class="rounded bg-slate-100 px-1 text-[0.9em]">RAG_REASONING</code>）。  </li>
<li>若嚴重度 ≥ <code class="rounded bg-slate-100 px-1 text-[0.9em]">ai.second_opinion_severity</code>（預設 BREACH），執行 <code class="rounded bg-slate-100 px-1 text-[0.9em]">crmp-challenger-v0</code>。  </li>
<li>分析師於 Demo Messenger <strong>Show evidence</strong>；可選擇以聊天挑戰。  </li>
<li>風險負責人覆核主分析＋挑戰者後 <strong>Close</strong> 或升級／要求控制。</li>
</ol>

<h3 id="5-2-控制項雙重確認-checker" class="text-lg font-semibold mt-6 mb-2">5.2 控制項雙重確認＋Checker</h3>
<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>操作者選擇建議行動（如封鎖帳戶）。  </li>
<li>雙重確認 → 模擬 Vantage admin ref＋連結。  </li>
<li>若需 Checker，於 Interventions／指示路徑核准。  </li>
<li>稽核＋脊柱記錄 Maker／Checker 結果。</li>
</ol>

<h3 id="5-3-ai-admin-變更" class="text-lg font-semibold mt-6 mb-2">5.3 AI Admin 變更</h3>
<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li>Maker 於 AI Admin 提出設定／模型／政策。  </li>
<li>不同 Checker 核准。  </li>
<li>自我核准被拒絕。</li>
</ol>

<h2 id="8-詳細驗收標準-原型閘道" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">8. 詳細驗收標準（原型閘道）</h2>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li><strong>技能＋挑戰者：</strong> 模擬 COPY BREACH → <code class="rounded bg-slate-100 px-1 text-[0.9em]">SKILL_MATCH</code>＋第二 AI 面板（挑戰時≥1 HIGH 改進）。  </li>
<li><strong>門檻：</strong> 預設 BREACH 下，純 WARN EQ 模擬<strong>不</strong>建立挑戰。  </li>
<li><strong>Messenger：</strong> Show evidence 貼出證據庫；Escalate 前進路徑；Dismiss／Close 更新狀態。  </li>
<li><strong>控制：</strong> 封鎖帳戶→雙重確認→admin_ref；需要時有 Checker 後續。  </li>
<li><strong>AI Admin：</strong> 需不同 Checker；禁止自我核准。  </li>
<li><strong>覆蓋：</strong> UAT 視窗 BREACH／CRITICAL 100% 已挑戰（允許回填）。  </li>
<li><strong>文件：</strong> PRD／TSD／手冊／UAT／生態英繁可渲染。  </li>
<li><strong>行動：</strong> ~390px messenger 列表→執行緒→返回，無文件級橫向溢出。</li>
</ol>
