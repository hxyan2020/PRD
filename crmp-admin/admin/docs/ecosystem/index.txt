<h2 id="7-precautions" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">7. Precautions</h2>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li><strong>Never</strong> grant AI service principals rights on blocklisted pages/functions/fields (<code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/security/ai-access</code>).  </li>
<li>Irreversible controls stay <strong>human-gated</strong>; second-AI <code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code> / <code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code> ⇒ mandatory human review.  </li>
<li>Maker/checker identities must be separated in <strong>IAM</strong>, not only in application logic.  </li>
<li>Run <strong>shadow mode</strong> (notify-only) before enabling any write adapter.  </li>
<li>Define and test <strong>kill-switches</strong> for auto skill execution, market-intel push, and each write adapter.  </li>
<li>Legal review before persisting client identifiers in evidence excerpts; set retention + redaction jobs.  </li>
<li>Cap AI spend and latency with SLOs; challenger must remain an <strong>independent</strong> decision path (no shared prompt cache with primary).  </li>
<li>Change-control: AI Admin setting changes always require a distinct checker.  </li>
<li>Do not auto-close Monitor tickets from AI alone on BREACH/CRITICAL without Risk Owner policy.  </li>
<li>Rehearse escalation path (Primary → Secondary → Risk Owner → Exec) in UAT before go-live.</li>
</ol>

<h2 id="5-時程階段-依依賴-非日曆承諾" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">5. 時程階段（依依賴，非日曆承諾）</h2>

<h3 id="階段-a-基礎鎖定" class="text-lg font-semibold mt-6 mb-2">階段 A — 基礎鎖定</h3>

<h3 id="階段-b-讀路徑上線" class="text-lg font-semibold mt-6 mb-2">階段 B — 讀路徑上線</h3>
<ul class="list-disc pl-5 my-2 space-y-1 text-sm">

<li>工單回寫＋完整稽核／脊柱  </li>
<li>緊急開關演練  </li>
</ul>

<h3 id="階段-d-優化" class="text-lg font-semibold mt-6 mb-2">階段 D — 優化</h3>
<ul class="list-disc pl-5 my-2 space-y-1 text-sm">
<li>挑戰模型多樣化  </li>

<li>多法人就緒（如需要）  </li>
</ul>

<p class="text-sm leading-relaxed my-2"><strong>順序原則：</strong> 風險負責人接受階段 B 的誤報與挑戰不同意流程前，不啟動階段 C 寫入適配。</p>

<h2 id="7-注意事項" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">7. 注意事項</h2>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li><strong>禁止</strong>授予 AI 服務主體黑名單頁面／功能／欄位權限。  </li>
<li>不可逆控制必須人工閘道；第二 AI <code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code>／<code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code> ⇒ 強制人工覆核。  </li>
<li>Maker／Checker 身分須在 <strong>IAM</strong> 分離，不能只靠應用邏輯。  </li>
<li>啟用任何寫入適配前先跑<strong>影子模式</strong>。  </li>
<li>定義並演練自動技能、情報推送、各寫入適配之<strong>緊急開關</strong>。  </li>
<li>證據含客戶識別前須法遵審查；設定保存與遮罩作業。  </li>
<li>以 SLO 限制 AI 成本與延遲；挑戰者須保持<strong>獨立</strong>決策路徑。  </li>
<li>AI Admin 設定變更永遠需要不同 Checker。  </li>
<li>BREACH／CRITICAL 不得僅由 AI 自動關閉 Monitor 工單（除非風險政策明文允許）。  </li>
<li>上線前以 UAT 演練升級路徑（Primary → Secondary → Risk Owner → Exec）。</li>
</ol>
