<h2 id="5-timeline-phased-effort-shape-not-calendar-promises" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">5. Timeline (phased — effort shape, not calendar promises)</h2>

<p class="text-sm leading-relaxed my-2">Cloud agents and vendors should plan by <strong>dependency phase</strong>, not by fixed week counts:</p>

<h3 id="phase-a-foundation-lock" class="text-lg font-semibold mt-6 mb-2">Phase A — Foundation lock</h3>
<ul class="list-disc pl-5 my-2 space-y-1 text-sm">
<li>RACI (Risk / Ops / AI / System) signed  </li>
<li>Data classification for evidence vault  </li>
<li>Environments (dev/stage/prod) + secrets  </li>
<li>UAT pack baseline with Risk Owner  </li>
</ul>

<h3 id="phase-b-read-path-production" class="text-lg font-semibold mt-6 mb-2">Phase B — Read-path production</h3>
<ul class="list-disc pl-5 my-2 space-y-1 text-sm">
<li>Live Monitor alarms into CRMP  </li>
<li>Dual-AI RCA (primary + <strong>independent challenger</strong>) on BREACH/CRITICAL  </li>
<li>Lark notify + “open in admin” (actions may still deep-link)  </li>
<li>Shadow dashboard: AI suggests, humans act outside write bus  </li>
</ul>

<h3 id="phase-c-supervised-write-path" class="text-lg font-semibold mt-6 mb-2">Phase C — Supervised write path</h3>
<ul class="list-disc pl-5 my-2 space-y-1 text-sm">
<li>Maker confirm in messenger/admin → control bus  </li>
<li>Checker approval for irreversible controls  </li>
<li>Ticket write-back + full audit/spine  </li>
<li>Kill-switch drills  </li>
</ul>

<h3 id="phase-d-optimisation" class="text-lg font-semibold mt-6 mb-2">Phase D — Optimisation</h3>
<ul class="list-disc pl-5 my-2 space-y-1 text-sm">
<li>Challenger model diversity (separate vendor/prompt)  </li>
<li>Market-intel precision / cost SLOs  </li>
<li>Multi-entity readiness if required  </li>
</ul>

<p class="text-sm leading-relaxed my-2"><strong>Suggested sequencing rule:</strong> do not start Phase C write adapters until Phase B false-alarm and challenger-disagreement workflows are accepted by Risk Owner.</p>

<h2 id="7-precautions" class="font-[family-name:var(--font-display)] text-2xl mt-8 mb-3">7. Precautions</h2>

<ol class="list-decimal pl-5 my-2 space-y-1 text-sm">
<li><strong>Never</strong> grant AI service principals rights on blocklisted pages/functions/fields (<code class="rounded bg-slate-100 px-1 text-[0.9em]">/admin/security/ai-access</code>).  </li>
<li>Irreversible controls stay <strong>human-gated</strong>; second-AI <code class="rounded bg-slate-100 px-1 text-[0.9em]">PARTIAL</code> / <code class="rounded bg-slate-100 px-1 text-[0.9em]">DISAGREE</code> ⇒ mandatory human review.  </li>
<li>Maker/checker identities must be separated in <strong>IAM</strong>, not only in application logic.  </li>
<li>Run <strong>shadow mode</strong> (notify-only) before enabling any write adapter.  </li>
<li>Define and test <strong>kill-switches</strong> for auto skill execution, market-intel push, and each write adapter.  </li>
<li>Legal review before persisting client identifiers in evidence excerpts; set retention + redaction jobs.  </li>
<li>Cap AI spend and latency with SLOs; challenger must remain an <strong>independent</strong> decision path (no shared prompt cache with primary).  </li>
<li>Change-control: AI Admin setting changes always require a distinct checker.  </li>
<li>Do not auto-close Monitor tickets from AI alone on BREACH/CRITICAL without Risk Owner policy.  </li>
<li>Rehearse escalation path (Primary → Secondary → Risk Owner → Exec) in UAT before go-live.</li>
</ol>
