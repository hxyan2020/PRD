SKILL-CRYPTO-OI-CONC

Perp OI concentration (≥35% one account)

Single account / cluster dominates open interest — liquidation cliff risk.

Risk ControlACTIVEM2-CRYPTO-OIauto-executeRisk Owner / Credit Desk

Written like a SKILL.md: when to use, when not to, prechecks, steps, evidence, stop conditions, and success criteria. The card is the summary; this page is the full playbook.

When to use
  • Use this skill when Top Account OI Share (per contract) (M2-CRYPTO-OI) is at or above warn 20% (desk attention) or breach 35% (act).
  • Severity must be WARN / BREACH. ≥35% one account can cascade the book on liq; 20% triggers position limit review.
  • Single account / cluster dominates open interest — liquidation cliff risk.
When not to use
  • Do not run this playbook on a single test login, isolated VIP override, or known UAT print.
  • Do not skip confirmation checks just because the primary indicator is red — related monitors may explain it.
  • Do not execute irreversible controls (halt symbol, block account, cut leverage, pause withdrawals) without the human gate listed below.
  • Do not close the case while the indicator is still at breach unless Risk Owner has accepted residual risk in writing.
Inputs
  • Primary indicator M2-CRYPTO-OI (Top Account OI Share (per contract)), comparator at or above, warn 20%, breach 35%.
  • Product Crypto · domain CRYPTO_EXCHANGE · severity WARN / BREACH.
  • Related monitor M2-CRYPTO-LIQ
  • Related monitor M2-CRYPTO-INS
  • Related monitor M2-WASH-020
Outputs
  • Lark / demo Messenger notify to the mapped channel.
  • AI analysis pack (skill path) plus evidence-vault rows.
  • Spine DETECT → AI_RCA → SKILL_EXECUTE events, plus INTERVENTION when gated.
  • Auto-step completion record; human-gated steps still require approval.
Prechecks
  1. 1. Confirm M2-CRYPTO-OI is not a stale snapshot (last_checked within the last 2 minutes).
  2. 2. Confirm LP/feed health is not independently in BREACH if this skill is credit- or book-risk.
  3. 3. Check M2-CRYPTO-LIQ — if it is also alarming, treat as a linked timeline, not a single-indicator event.
  4. 4. Check M2-CRYPTO-INS — if it is also alarming, treat as a linked timeline, not a single-indicator event.
  5. 5. Check M2-WASH-020 — if it is also alarming, treat as a linked timeline, not a single-indicator event.
  6. 6. Confirm there is a matching live alert / ticket before paging Exec.

Evidence to collect
  • Monitor snapshot for M2-CRYPTO-OI (observed vs warn 20% / breach 35%).
  • Messenger thread: ALERT + AI_REPORT + any ESCALATION card.
  • Primary RCA + second-AI challenger verdict if severity is BREACH or CRITICAL.
  • Co-moving indicator M2-CRYPTO-LIQ.
  • Co-moving indicator M2-CRYPTO-INS.
  • Co-moving indicator M2-WASH-020.
  • Audit / spine events for this alert_id before any control is marked live.
Stop conditions
  • Stop paging if M2-CRYPTO-OI has been back below warn 20% for 15 minutes and no linked BREACH remains.
  • Stop irreversible controls if the second AI DISAGREEs and Risk Owner has not overridden.
  • Abort auto-execute if this skill is marked manual or a human gate step is AWAITING_HUMAN.
Success criteria
  • Alert acknowledged with a named owner within the SLA below.
  • Playbook steps completed (or explicitly skipped with a note) in spine + audit.
  • Human-gated controls have maker + checker (or Risk Owner) recorded.
  • Look like a known good outcome: CASE-OI-0719 — PREVENTED.
